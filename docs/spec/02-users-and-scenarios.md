# 02 · 目标用户与核心场景

## 1. 为什么先写场景再写功能

MobaXterm 的帮助文档里有 13 条 FAQ 是在解释「为什么我的功能没按预期工作」（字符集乱码、backspace 输出 `^H`、SSH 浏览器不弹出、连接被重置、`known_hosts` 冲突……）。
这些不是文档写得不好，而是**功能设计时没有把场景想清楚**——设计者想的是「提供 20 个会话配置项」，用户想的是「线上 502 了，我要 30 秒内看到错误日志」。

规格必须从后者出发。本文的 6 条端到端任务流会**直接变成 E2E 测试用例**（见 `design/15` §5），
并且是判断「这个功能做完了没有」的最终依据：功能存在但流跑不通 = 没做完。

## 2. 用户画像

按「使用频次 × 权限高度」排序，前两类是主目标。

### P1 · 运维 / SRE 工程师（主要目标）

| 维度 | 描述 |
|---|---|
| 规模 | 管 20~500 台机器，含跳板机、生产/预发/测试三套环境 |
| 平台 | Windows（公司发）或 macOS（自选），常常两者都有 |
| 现有工具 | MobaXterm / Xshell / SecureCRT + 一堆脚本 |
| 日常 | 看日志、重启服务、改配置、传包、查端口、开隧道连数据库 |
| 痛点 | ① 环境多了以后会话管理混乱，靠命名约定硬撑；② 生产凭据散落在多个工具里；③ 换机器/换系统要重建全部会话；④ 出事时要在多个工具间跳，慢一秒都是事故 |
| 换用的触发点 | **一次能把 MobaXterm 的会话全导进来，且导入后立刻能用**（这是唯一的入场券） |
| 会因此弃用的原因 | 终端卡顿、复制粘贴行为不一致、快捷键变了、跳板机连不上 |

### P2 · 后端 / 全栈开发工程师（主要目标）

| 维度 | 描述 |
|---|---|
| 规模 | 连 3~15 台（开发机、测试机、CI 机器、云主机） |
| 平台 | macOS 为主，Windows + WSL2 次之 |
| 现有工具 | 系统终端 + `ssh config` + VS Code Remote + 偶尔 WinSCP |
| 日常 | 部署、看容器日志、改远端配置、传构建产物、开隧道连测试库 |
| 痛点 | ① 图形化工具都太重，配置不透明；② 想脚本化但工具没有 CLI；③ 文件传输要另开一个工具；④ 跳板机后面的机器每次都要手动开两个标签页手输 `ssh` |
| 换用的触发点 | **能用命令行驱动它**（`wt connect prod-db --tunnel 3306:localhost:3306`），并且配置文件是纯文本可进 Git |
| 会因此弃用的原因 | 配置是二进制/数据库，没法版本管理；CLI 覆盖不全 |

### P3 · 数据库管理员（DBA）

| 维度 | 描述 |
|---|---|
| 日常 | 连库（多数通过 SSH 隧道）、看慢日志、导数据、重启实例 |
| 特殊需求 | **隧道是刚需**，且要长期稳定、能自动重连、能看到隧道状态；大文件传输（几十 GB 的备份） |
| 痛点 | 隧道断了不知道、重连要重新配、大文件传到一半失败要重来 |
| 对应需求 | `NET-001/004/005/006`、`FIL-007/019` |

### P4 · 网络 / 系统集成工程师

| 维度 | 描述 |
|---|---|
| 日常 | 串口连交换机/路由器、Telnet 连老设备、抓包、端口扫描 |
| 特殊需求 | **串口**（波特率/数据位/停止位/流控）、Telnet 的字符模式协商、抓包 |
| 痛点 | 现代工具普遍砍掉了串口和 Telnet |
| 对应需求 | `SES-002/011`、`NET-012/013` |

### P5 · 企业 IT 管理员（**采购决策者，不是使用者**）

| 维度 | 描述 |
|---|---|
| 关心 | 能不能统一分发配置？能不能禁用不安全功能？有没有审计？许可是否合规？能不能私有化部署更新源？ |
| 不关心 | 终端渲染多快、配色多好看 |
| 对应需求 | `SET-008`、`SEC-009/010`、`EXT-008`、`SYS-007`（可指向内网更新源）、`spec/01` §5 许可 |
| 关键判定 | **如果这一类的需求不满足，前面四类用户根本拿不到这个软件**（采购环节被否） |

### 非目标用户

- 只用一次 SSH 的普通用户（用系统终端即可）
- 需要远程控制他人电脑的消费者（属反目标，见 `spec/01` §3.2）
- 移动端用户

## 3. 六条端到端任务流

每条流都给出：**触发 → 步骤 → 成功判据 → 失败模式**。成功判据要能写成断言。

### FLOW-1 · 首次使用与迁移

> 场景：运维老张用了 6 年 MobaXterm，公司要求评估开源替代。他只有 10 分钟耐心。

```
安装 → 首次启动 → 引导页出现「从 MobaXterm 导入」
     → 自动探测 %USERPROFILE%\Documents\MobaXterm\MobaXterm.ini
     → 勾选要导入的会话（树形预览，显示将导入 47 个会话 / 6 个文件夹）
     → 询问主密码（若原文件加密）→ 输入 → 校验通过
     → 导入完成，报告：47 成功 / 2 因密码无法解密需重输 / 1 协议不支持（Rlogin）
     → 双击第一个会话 → 连上
```

**成功判据**
- 从启动到连上第一台机器 ≤ 5 次点击、≤ 2 分钟（不含输入密码）
- 会话树结构（文件夹层级、命名、排序）与 MobaXterm 一致
- 密码字段：能解密则填充；不能解密则标记「需重新输入」而非静默丢弃
- 不支持的协议**列出来**，不静默跳过

**失败模式与要求**
- 找不到 ini → 提供手动选择路径 + 说明各版本默认位置
- ini 加密且用户忘记主密码 → 允许「只导入结构，不导入密码」，并明确告知
- 导入中途失败 → 事务性：要么全成功，要么回滚到导入前状态（不能留半截会话树）

对应需求：`SES-020`、`SET-013`、`SEC-001`

### FLOW-2 · 生产排障（最核心的一条）

> 场景：线上 502，需要 30 秒内看到错误日志。

```
点击「生产」文件夹 → 右键「启动全部会话」(3 台) 或直接点单台
  → SSH 经跳板机（bastion）→ 目标机，密钥认证，无密码提示
  → 终端就绪
  → 输入 tail -f /var/log/nginx/error.log
  → 日志滚动，终端里 "error" 被语法高亮标红
  → Ctrl+Shift+F 搜 "upstream timed out"，跳到命中行
  → 选中一段日志 → 右键复制 → 粘贴到 IM
  → 左侧文件浏览器已自动跟到 /var/log/nginx/（Follow path）
  → 右键 error.log → 下载到本地
```

**成功判据**
- 跳板机链路在**一次点击**内完成（不允许用户手动开两个标签页再手输 ssh）
- 从点击到可输入 ≤ 2 s（含跳板机，局域网）
- `tail -f` 持续输出 10 分钟不掉线、不卡 UI、不丢行
- 语法高亮规则可自定义，且对 `tail -f` 的增量行生效
- 文件浏览器跟随：终端 `cd` 后 ≤ 500 ms 内同步路径
- 下载时显示进度、可取消、失败可重试

**失败模式与要求**
- 跳板机认证失败 → 明确指出是**哪一跳**失败（跳板机 / 目标机），不要笼统报「连接失败」
- 目标机 `sshd` 关闭了 `AllowTcpForwarding` → 报错要指明是这一项，并给出配置行
- 网络中断 → 自动重连（可配次数/间隔），重连成功后**保留滚动缓冲**并插入一条分隔线标明断连时段
- 日志文件无读权限 → 提示具体路径与所需权限，给出 `sudo` 建议命令

对应需求：`SES-001/024`、`TER-001/009/010/015`、`FIL-001/017`、`NET-004`

---

### FLOW-3 · 改远端配置并生效

> 场景：要改测试环境 nginx 的一个 `location` 块。

```
左侧 SFTP 浏览到 /etc/nginx/conf.d/
  → 双击 site.conf → 内嵌编辑器新标签打开（语法高亮 = nginx）
  → 改两行 → Ctrl+S
  → 保存时：先写远端临时文件 → 原子 rename → 保留原属主与权限
  → 编辑器显示「已保存到 root@host:/etc/nginx/conf.d/site.conf」
  → 终端里 nginx -t && systemctl reload nginx
```

**成功判据**
- 打开到可编辑 ≤ 1.5 s（100 KB 文件）
- 保存保留原文件的 **mode / owner / mtime 策略**（mtime 更新，mode/owner 不变）
- 远端无写权限 → 保存前就提示（而不是写完才发现），并给出「以 sudo 保存」的选项
- 保存失败（磁盘满、连接断）→ **不丢失本地编辑内容**，保留为未保存状态并允许「另存到本地」
- 二进制文件被误双击 → 检测到 NUL 字节后拒绝以文本打开，提示「用图片查看器/下载」

**失败模式与要求**
- 文件在编辑期间被他人修改 → 保存时检测 mtime/size 变化，提示「远端已变更」并给 diff，让用户选择覆盖/放弃
- 超大文件（> 20 MB）→ 拒绝在编辑器打开，提示改用下载或 `less`

对应需求：`FIL-001/005/011`、`SEC-011`

---

### FLOW-4 · 连一台 Windows 服务器

> 场景：财务系统的 Windows Server 只能 RDP，需要把本地一个 Excel 传上去。

```
新建 RDP 会话 → 填 host/user → 勾选「驱动器重定向」+「剪贴板重定向」
  → 连接（NLA/CredSSP 自动协商）
  → 远程桌面出现在标签内，自适应窗口大小
  → 远程打开「我的电脑」→ 看到「WindTerm 重定向驱动器」盘符
  → 把本地 Excel 复制 → 远程粘贴 → 成功
  → 需要按 Ctrl+Alt+Del → 工具栏按钮「发送 Ctrl+Alt+Del」
  → 关闭标签 → 会话保持/注销按配置
```

**成功判据**
- 标签内渲染，不是独立窗口；可全屏、可缩放、可随窗口自适应分辨率
- 剪贴板文本 + 图片 + 文件（文件走驱动器重定向）双向可用
- 中文输入法在远程桌面内可用
- 断开后本地不留悬挂进程
- 认证失败的错误码要翻译成人话（`0x80090311` → 「身份验证失败：用户名或密码错误 / 账号被锁定」）

**失败模式与要求**
- 服务器只允许 NLA 而我们协商失败 → 明确提示，不要无限重连
- 证书不受信（自签）→ 展示证书指纹并要求显式确认，**不提供「永久忽略」一键选项**
- 网络抖动 → 自动重连并恢复会话（RDP 的 autoreconnect cookie），失败则保留窗口让用户手动重连

对应需求：`GUI-015/017/018/022/024/026`、`SEC-005`

---

### FLOW-5 · 开隧道连内网数据库

> 场景：测试库只允许从跳板机访问。

```
隧道管理器 → 新建
  → 名称 "test-db"、类型 本地转发、监听 127.0.0.1:13306
  → 经由 会话 "bastion"（复用其认证）
  → 目标 db-internal:3306
  → 启动 → 状态变绿，显示「已转发 3 个连接，累计 12.4 MB」
  → DBeaver 连 127.0.0.1:13306 → 通
  → 电脑休眠唤醒 → 隧道自动重连 → DBeaver 查询恢复正常（无需重开）
```

**成功判据**
- 隧道可绑定 127.0.0.1 或 0.0.0.0（后者需显式警告）
- 端口冲突时给出明确错误与「改用随机端口」按钮
- 断线自动重连（可配），重连期间**不关闭监听 socket**（避免客户端收到 RST）
- 状态可见：连接数、字节数、最后错误、启动时间
- 支持随应用启动 / 随会话启动

**失败模式与要求**
- 目标端口不可达 → 错误必须区分「跳板机不通」「跳板机到目标不通」「目标拒绝连接」
- 隧道长期空闲被中间设备断开 → 支持 keepalive 并可配

对应需求：`NET-001/002/003/004/005/006`

---

### FLOW-6 · 批量操作 20 台机器

> 场景：给 20 台 Web 节点统一改一个参数。

```
多选 20 个会话 → 右键「多执行」
  → 20 个终端按网格排列（可选 4/8/16 宫格）
  → 在一个「输入框」里敲命令 → 20 台同时收到
  → 执行 systemctl status nginx
  → 结果按「一致 / 不一致」分组：18 台 active，2 台 failed → 只展开那 2 台
  → 对 2 台单独修正
```

**成功判据**
- 20 台并发连接在 10 s 内全部就绪（或明确显示哪几台超时）
- 输入广播有「延迟发送」与「确认后发送」两种模式（防误操作生产）
- **危险命令拦截**：匹配到 `rm -rf /`、`mkfs`、`dd of=/dev/`、`shutdown` 等模式时二次确认（可配白名单）
- 结果聚合视图：能一眼看出「哪几台输出不同」
- 单台失败不影响其他台

**失败模式与要求**
- 部分会话未就绪 → 广播时跳过并标注，不要静默丢命令
- 输出量巨大 → 聚合视图按需加载，不要一次性渲染 20 × 10 万行

对应需求：`TER-002/004`、`SEC-011`

## 5. 使用环境假设

规格中所有性能与兼容性承诺都基于以下假设，超出假设的场景不做承诺：

| 维度 | 假设 |
|---|---|
| 客户端 OS | Windows 10 1809+ / Windows 11；macOS 12+（Apple Silicon 与 Intel）；Ubuntu 22.04+ / Fedora 38+ / Debian 12+ |
| 显示 | 单屏 ≥ 1280×720；支持 HiDPI（100%~250% 缩放）；多屏为增强场景 |
| 输入 | 有物理键盘；**无鼠标中键**的触控板用户必须能完成全部操作（MobaXterm 的右键粘贴问题就出在这） |
| 网络 | 客户端到跳板机 RTT ≤ 200 ms 可用；RTT > 500 ms 时只保证不崩、不承诺体验 |
| 服务端 | OpenSSH 7.4+（CentOS 7 基线）；Windows Server 2012 R2+；VNC Server 为 RFB 3.8 |
| 并发 | 单实例 ≥ 50 个会话、≥ 20 个并发传输 |
| 权限 | 客户端不需要管理员权限即可运行全部核心功能（安装除外） |
| 语言 | 界面 zh-CN / en-US；终端编码 UTF-8 默认，兼容 GB18030/GBK/Big5/ISO-8859-1 |
