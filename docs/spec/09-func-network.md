# 09 · 功能规格 · 网络工具与隧道

承接需求：`NET-001`~`NET-018`

## 1. 范围与设计立场

MobaXterm 的隧道工具（MobaSSHTunnel）是它被低估的功能：图形化配置 `-L/-R/-D`，比记命令行参数友好得多。但它有三个不足：

1. **隧道是「会话的附属物」**——不能独立于会话存在，也不能被脚本管理；
2. **状态不可见**——断了不知道，重连要手动；
3. **不能随应用启动**——每次开机都要手动点。

我们的规格把隧道提升为**一等对象**：有独立 ID、独立生命周期、可脚本控制、可观测。

## 2. 需求条目

### NET-001 · 本地端口转发 `-L`

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `F:ssh-tunnels` `D:2.1.5` |

**语义**：`本地监听 L:LPort` → 经 SSH 会话 → 目标 `TH:TPort`。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | string | 自动 | 稳定标识，供 CLI 引用 |
| `name` | string | — | 显示名 |
| `type` | enum | `local` | `local`/`remote`/`dynamic` |
| `listenHost` | string | `127.0.0.1` | `127.0.0.1`/`::1`/`0.0.0.0`/具体 IP |
| `listenPort` | u16 | 0（自动） | 0 表示由系统分配，启动后回填实际端口 |
| `targetHost` | string | — | 从 SSH 服务端视角解析 |
| `targetPort` | u16 | — | |
| `viaSessionId` | ref | — | 承载隧道的 SSH 会话 |
| `autoStart` | enum | `manual` | `manual`/`onAppStart`/`onSessionStart` |
| `keepAlive` | bool | true | 复用 SSH keepalive |
| `reconnect` | object | 见 §3.4 | |

**行为规格**

1. **监听地址安全性**：选 `0.0.0.0` 时显示红色警告「局域网内任何人都能通过此端口访问目标服务」，需勾选确认。
2. **端口冲突**：启动前检测；冲突时错误信息包含占用进程（能取到时）并给出「改用随机端口」按钮。
3. **目标解析在远端**：`targetHost` 由 SSH 服务端解析（`direct-tcpip` 语义），不是本地解析。UI 需说明「目标主机名在服务器侧解析」。
4. **连接计数**：显示当前活跃连接数、累计连接数、上/下行字节。
5. **半关闭处理**：一端 `EOF` 时向另一端发 `EOF`，等待对端关闭，避免 `RST` 丢失数据。

**验收标准**

- [ ] AC-1 转发 `127.0.0.1:13306 → db:3306`，本地 MySQL 客户端可连接并执行查询
- [ ] AC-2 `listenPort=0` 时启动后回填实际端口，UI 显示 `127.0.0.1:54321`
- [ ] AC-3 选 `0.0.0.0` 必须确认，取消则隧道不启动
- [ ] AC-4 端口被占用时错误包含占用进程名（同用户可查到时）
- [ ] AC-5 传输 1 GB 数据后字节计数准确（误差 < 1%）

### NET-002 · 远程端口转发 `-R`

**语义**：`远端监听 RH:RPort` → 经 SSH → 本地 `LH:LPort`。

| 字段 | 说明 |
|---|---|
| `remoteListenHost` | 远端监听地址；默认 `localhost` |
| `remoteListenPort` | 远端端口；0 表示由服务端分配（需服务端支持 `tcpip-forward` 返回端口） |

**关键约束**

1. 服务端 `GatewayPorts no`（OpenSSH 默认）时，远端只能监听 `127.0.0.1`。请求其他地址会被拒绝——错误信息必须说明这一点，而不是笼统的「转发失败」。
2. 服务端 `AllowTcpForwarding no` 时直接拒绝。
3. 端口 0 分配：OpenSSH 7.6+ 支持返回分配的端口；老版本需用户指定。

**验收标准**

- [ ] AC-1 在远端 `ss -tln` 中看到监听端口，且从远端本机可连
- [ ] AC-2 `GatewayPorts no` 时请求 `0.0.0.0` 失败，错误信息含 `GatewayPorts`
- [ ] AC-3 端口 0 时服务端返回实际端口并回填

### NET-003 · 动态转发 SOCKS5 `-D`

**语义**：本地 SOCKS5 代理 → 经 SSH → 任意目标。

| 项 | 要求 |
|---|---|
| 版本 | SOCKS5（RFC 1928）+ 用户名密码认证（RFC 1929，可选） |
| 命令 | 只支持 `CONNECT`；`BIND`/`UDP ASSOCIATE` 不支持（返回 `0x07 Command not supported`） |
| 地址类型 | IPv4 / IPv6 / 域名（域名由远端解析） |
| 用途 | 浏览器代理、`curl --socks5`、`git` 的 `ALL_PROXY` |

**验收标准**

- [ ] AC-1 `curl --socks5-hostname 127.0.0.1:1080 http://internal/` 成功
- [ ] AC-2 域名由远端解析（本地 DNS 查不到的内网域名可用）
- [ ] AC-3 开启认证后，无凭据连接被拒绝并返回 `0x02`

### NET-004 · 图形化隧道管理器

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `F:ssh-tunnels` `D:2.1.5` |

**界面**

```
┌──────────────────────────────────────────────────────────────┐
│ 隧道                                    [+ 新建] [导入] [导出] │
├──────────────────────────────────────────────────────────────┤
│ ● test-db     L 127.0.0.1:13306 → db:3306   via bastion       │
│               3 连接 · ↑12.4 MB ↓88.1 MB · 运行 2h14m          │
│ ○ redis-dev   L 127.0.0.1:16379 → redis:6379 via bastion      │
│               已停止 · 上次错误：目标拒绝连接（Connection refused）│
│ ● proxy       D 127.0.0.1:1080              via bastion       │
└──────────────────────────────────────────────────────────────┘
```

**行为**

1. 状态灯：绿（运行）/ 灰（停止）/ 黄（重连中）/ 红（失败）。
2. 行内操作：启动/停止、编辑、复制、删除、查看日志。
3. 分组：按「承载会话」分组显示（同一 SSH 会话下的隧道归在一起）。
4. 排序：按名称/状态/创建时间。
5. 批量：全选启动/停止。
6. 空状态引导：「隧道可以把远端端口映射到本地，用于连接只允许从服务器访问的服务（如数据库、Redis）。」+ 「新建隧道」按钮。

**验收标准**

- [ ] AC-1 新建 → 启动 → 停止 → 删除 全流程可用
- [ ] AC-2 10 条隧道同时运行，状态与统计实时更新（≤ 2 s 刷新）
- [ ] AC-3 承载会话断开时，其下隧道全部变黄（重连中）或红（失败）并显示原因

### NET-005 · 隧道生命周期

| 策略 | 行为 |
|---|---|
| `manual` | 只能手动启停 |
| `onAppStart` | 应用启动后自动启动（若承载会话未连接，先连接） |
| `onSessionStart` | 承载会话连接成功后自动启动 |

**退出应用时**：默认停止全部隧道；可配「保持运行」（需要后台进程，暂不支持，`P3`）。

**崩溃恢复**：应用异常退出后重启，标记为 `onAppStart` 的隧道自动恢复；其余显示「上次未正常停止，是否恢复？」。

### NET-006 · 隧道状态与统计

| 指标 | 说明 |
|---|---|
| 状态 | 停止/启动中/运行/重连中/失败 |
| 活跃连接数 | 当前打开的转发连接 |
| 累计连接数 | 会话期内总数 |
| 上行/下行字节 | 精确到字节，UI 格式化 |
| 最后错误 | 最近一次错误（含时间） |
| 运行时长 | |
| 最近 60 秒吞吐 | 迷你折线图（P2） |

**日志**：每条隧道独立日志（连接建立/关闭、错误、重连），保留最近 1000 条，可导出。

| 字段 | 值 |
|---|---|
| 优先级 | P2 · 兼容性 C2 |

|---|---|

### NET-009 · 内置 SSH/SFTP 服务端

| 项 | 要求 |
|---|---|
| 用途 | 「让同事临时连进来取文件」/「在没有 SSH 的机器上开一个入口」 |
| 认证 | **仅公钥**（不接受密码，避免弱口令） |
| 授权密钥 | 从用户已有密钥中选择，或粘贴公钥 |

| 监听 | 默认 `127.0.0.1:2222`；改 `0.0.0.0` 需确认 |
| 生命周期 | 默认「会话结束即停」；可配定时停止（最长 24h） |
| 审计 | 记录连接与文件访问 |

**为什么不做 Telnet/TFTP 服务端**：见 `spec/03` §7 排除清单。明文协议的服务端等于主动开后门。

### NET-012 · 抓包（TCPCapture）

| 字段 | 值 |
|---|---|
| 优先级 | P2 · 兼容性 C2 |

**依赖（不随包分发）**

| 平台 | 依赖 | 说明 |
|---|---|---|
| Windows | Npcap（需用户安装，安装时勾选「WinPcap API 兼容模式」） | 免费版限制再分发 |
| macOS | 系统 `libpcap` + `chmodbp4` 或 `sudo` | |
| Linux | `libpcap` + `CAP_NET_RAW` 或 `sudo` | |

**能力**

| 项 | 要求 |
|---|---|

| 过滤 | BPF 表达式（`tcp port 22`），提供常用预设 |
| 实时列表 | 时间、源/目的、协议、长度、摘要 |
| 详情 | 展开显示各层头部（Ethernet/IP/TCP/UDP/TLS 记录层） |
| 导出 | `.pcap`（Wireshark 可打开） |
| 限制 | 抓包缓冲上限（默认 100 MB），超出停止并提示 |

**缺失依赖时的行为**：不报错崩溃，显示「抓包需要 Npcap，未检测到」+ 官方下载链接 + 「我已安装，重新检测」按钮。

### NET-013 · 端口监听与扫描

| 功能 | 实现 |
|---|---|
| 本机监听列表 | 枚举本机 TCP/UDP 监听端口 + 进程名 + PID + 用户；可排序/过滤；可「结束进程」（需确认） |
| 远端监听列表 | 经 SSH 执行 `ss -tlnp`（回退 `netstat -tlnp`）并解析 |
| 远端端口扫描 | **不实现扫描器**。改为「批量端口连通性测试」：对指定主机的端口列表逐个 `direct-tcpip` 探测（这本身就是「从服务器视角看端口是否可达」，比外部扫描更准） |

**为什么不做端口扫描器**：扫描器是攻击工具，企业安全策略必然禁止；而运维真正需要的是「从这台服务器能不能连到那个端口」，用 SSH 通道探测更准确也更合规。

### NET-014 / NET-015 · httping / iperf

| 需求 | 决策 |
|---|---|
| `NET-014` | `P3`。用内置 HTTP 探测器替代：显示 DNS/TCP/TLS/首字节/总耗时、状态码、证书信息。不捆绑 `httping` 二进制 |
| `NET-015` | `P3`。用「SSH 通道吞吐测试」替代：在目标机上 `dd if=/dev/zero` 或读文件，测端到端吞吐。完整 iperf3 客户端 P3 |

### NET-016 · 网络诊断工具箱

| 工具 | 实现 | 说明 |
|---|---|---|
| Ping | ICMP（需权限）或 TCP connect（无需权限） | 默认 TCP，可切 ICMP；显示每次 RTT 与丢包率 |
| Traceroute | UDP（Unix 风格）或 ICMP | 显示每跳 IP 与 RTT；可解析主机名（可关，避免 DNS 慢） |
| DNS 查询 | `A`/`AAAA`/`CNAME`/`MX`/`TXT`/`NS`/`SOA`/`PTR` | 可指定 DNS 服务器；显示 TTL 与响应时间 |
| 端口连通 | TCP connect + 可选 TLS 握手 + banner 读取 | 见 `NET-017` |
| TLS 证书检查 | 连接并读取证书链 | 主体/颁发者/有效期/指纹/协议版本/加密套件/是否过期 |
| `nc` 等价 | 建立 TCP/UDP 连接，手动发数据 | 用于探测自定义协议 |

**统一交互**：每个工具一个面板，参数在上、结果在下、可复制为文本、可导出 JSON（便于脚本）。

### NET-017 · 端口连通性测试

输入 `host:port` → 输出：

```
目标        db-internal:3306
DNS 解析     ✓ 2 ms   10.0.3.44（内网 DNS 10.0.0.2）
TCP 连接     ✓ 8 ms   （本地直连）
应用层       ✓ MySQL 8.0.34 握手包（读到 banner）
─────────────────────────────
结论         端口可达，服务正常
```

**多路径对比**（增强）：同一目标从「本地」与「经会话 X」两个视角分别测试，并排显示——这是排障时最有用的信息（「我本地连不上，但服务器能连上」）。

### NET-018 · 隧道导入导出

- 随会话一起导出（JSON）。
- 从命令行文本导入：解析 `ssh -L 13306:db:3306 -R 8080:localhost:80 -D 1080 user@host`，生成对应隧道并关联到该 host 的会话。
- 导出为 `ssh` 命令行文本（便于分享给不用本产品的同事）。

## 3. 隧道引擎规格

### 3.1 数据流

```
本地监听 socket
      │ accept
      ▼
  ┌─────────┐   分配 channel    ┌──────────────┐
  │ 转发器   ├──────────────────►│ SSH 连接      │
  └─────────┘  direct-tcpip     │ (承载会话)    │
      │                        └──────┬───────┘
      │ 双向拷贝 + 背压                  │
      ▼                                ▼
   客户端                          目标服务
```

### 3.2 背压

隧道是纯转发，**不能无界缓冲**。每方向使用固定大小缓冲（默认 64 KB），写阻塞时停止从对端读，依赖 TCP 自身的窗口机制传导背压。禁止「读到内存里排队」。

### 3.3 连接数限制

| 限制 | 默认 | 说明 |
|---|---|---|
| 单隧道最大并发连接 | 128 | 超出时拒绝新连接并记录 |
| 全局最大并发连接 | 1024 | |
| 单连接空闲超时 | 0（不超时） | 数据库连接可能长时间空闲，不能默认超时 |

### 3.4 重连策略

| 参数 | 默认 |
|---|---|
| 触发条件 | 承载 SSH 会话断开 |
| 重试次数 | 无限（隧道是长期设施） |
| 退避 | 1s → 2s → 4s → 8s → 16s → 30s（上限） |
| 重连期间监听 socket | **保持打开**（不关闭，避免客户端收到 RST）；新连接排队等待（队列长度 32），超时后拒绝 |

> 「保持监听」是与简单实现的关键差异：如果重连时关闭再打开监听端口，客户端会立刻收到 `Connection refused`，正在执行的事务全部失败。保持监听 + 排队等待可以让客户端「卡一下然后继续」。

### 3.5 错误分类

| 情况 | 错误信息 |
|---|---|
| 承载会话未连接 | 「承载会话 bastion 未连接，无法启动隧道」 |
| 监听端口占用 | 「端口 13306 已被进程 mysqld（PID 1234）占用」 |
| 远端拒绝转发 | 「服务器禁止 TCP 转发（AllowTcpForwarding no）」 |
| 目标不可达 | 「跳板机能连到目标主机，但目标端口拒绝连接（Connection refused）」 |
| 目标 DNS 失败 | 「服务器无法解析目标主机 db-internal（Name or service not known）」 |

**分层错误是本域的硬要求**：必须区分「本地监听失败」「SSH 通道失败」「远端到目标失败」三层。
