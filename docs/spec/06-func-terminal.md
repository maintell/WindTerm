# 06 · 功能规格 · 终端仿真

承接需求：`TER-001`~`TER-035`

## 1. 范围与技术立场

终端是本产品使用时长最高的界面。规格要回答两个问题：**支持哪些 VT 能力**，以及**在什么条件下比 MobaXterm 更好**。

### 1.1 为什么不在第一版自研 VT 内核

自研一个能通过 `vttest` 全量用例的 VT 仿真器是 6~12 人月的工作量，且此后每个边缘序列（`DECSET 2026`、`OSC 133`、`SGR 58` 下划线色…）都是长期维护负担。

**决定（ADR-0004）**：v1 使用 `@xterm/xterm` 5.x 作为 VT 解析与渲染内核，运行在 WebView 中。
理由是它的 conformance 已被大量产品验证，且我们真正需要差异化的部分（搜索、日志、高亮、跟随路径、流控）都能通过它的 API 或外挂实现。

**代价与缓解**：

| 代价 | 缓解 |
|---|---|
| 大量输出时性能天花板 | 信用制背压（`TER-034`），保证「慢但不丢」；M0 实测 `cat` 100 MB 的表现并写入 `NFR-003` |
| 内存随滚动缓冲线性增长 | 缓冲上限 + 超限淘汰 + 「导出并清空」动作 |
| 无法直接拿到结构化屏幕内容 | 通过 `buffer.active.getLine()` 读取行文本，满足搜索/高亮/导出 |
| JS 侧持有终端状态，与 Rust 核心割裂 | 定义 `TerminalBackend` trait，为将来切换到 Rust 内核（`windterm-term`）留接口；切换不影响上层功能 |

> 若 M0 实测发现 xterm.js 在 20 MB/s 下无法满足 `NFR-003`，则启用备选方案：Rust 侧 `vte` + 自研网格 + WebGL2 渲染。该备选方案的风险与工作量已在 ADR-0004 中评估。

### 1.2 VT 能力基线

必须完整支持的层次（按优先级）：

| 层 | 内容 | 优先级 |
|---|---|---|
| L1 基础 | ASCII/UTF-8、`CUP/CUU/CUD/CUF/CUB`、`ED/EL`、`SGR`（含 256 色与 24 位色）、滚动区 `DECSTBM`、`IND/RI/NEL`、制表位、`DECAWM` | P0 |
| L2 会话 | 主/备用屏（`?1049`/`?47`/`?1047`）、`DECSC/DECRC`（含颜色与字符集）、`OSC 0/1/2` 标题、`OSC 52` 剪贴板、`OSC 8` 超链接、`OSC 7` 当前目录、`OSC 133` 提示符标记 | P0（`OSC 8` P2、`OSC 133` P2） |
| L3 交互 | 鼠标上报（`?1000/1002/1003/1005/1006/1015`）、`?2004` bracketed paste、`?1` 应用光标键、`?25` 光标可见、焦点事件（`?1004`） | P0 |
| L4 字符集 | `SCS` 字符集切换、`DEC Special Graphics` 画线符、East-Asian Width、组合字符、零宽连接符 | P0 |
| L5 高级 | Sixel、iTerm2 inline image、kitty graphics、`SGR 58` 下划线色、`SGR 4:x` 下划线样式、`DECSET 2026` 同步输出 | P2（Sixel 见 `TER-026`） |
| L6 遗留 | VT52 模式、`DECALN`、`DECCOLM`（80/132 列切换） | P3 |

**conformance 验证方法**（`design/15` §4）：`vttest` 全量手工走查 + `esctest` 自动化子集，结果作为发布门槛。

## 2. 需求条目

### TER-001 · 多标签

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `F:terminal` `D:1.3` |

**行为规格**

1. 标签栏位于顶部（可配到底部）；标签宽度自适应，最小 120 px，超出后横向滚动并显示左右箭头。
2. 标签内容：图标（会话类型）+ 名称 + 活动指示点 + 关闭按钮（悬停显示）。
3. 名称来源优先级：用户重命名 > 远端 `OSC 2` 标题（未锁定时）> 会话名。远端标题过长时截断并保留完整 tooltip。
4. 操作：单击切换、中键关闭、拖拽排序、双击重命名、右键菜单（分离/复制/重命名/关闭其他/关闭右侧/关闭全部）。
5. 溢出时 `Ctrl+Tab` 循环顺序按**最近使用**（MRU）而非标签位置——这与浏览器一致，减少误切。
6. 关闭有前台进程运行的标签时确认（`TER-018`）。

**验收标准**

- [ ] AC-1 打开 30 个标签后，标签栏可横向滚动，`Ctrl+Tab` 按 MRU 顺序切换
- [ ] AC-2 远端执行 `printf '\033]2;MY TITLE\007'`，标签名变为 `MY TITLE`；锁定标题后不再变化
- [ ] AC-3 拖拽标签重排后，重启应用顺序保持

### TER-002 · 分屏（2/4 宫格）

| 字段 | 值 |
|---|---|
| 优先级 | P1 · 兼容性 C1 |
| 来源 | `D:1.3` `D:5.3` |

**行为规格**

1. 三种预设：2 分屏（垂直/水平）、4 分屏（2×2）。
2. 分屏的每个格子里放一个**标签组**，格子内仍可用标签切换——这与 MobaXterm 的「分屏只是显示多个终端」不同，但更符合实际使用（每个格子里可能需要多台机器）。
3. 分屏内可再分屏（递归），最大深度 3；超过时禁用并提示。
4. 分隔条可拖拽调整比例，双击复位为均分。
5. 关闭某个格子时，其中的标签移到相邻格子，不丢失会话。
6. 分屏布局随工作区保存（`SET-011`）。

**验收标准**

- [ ] AC-1 进入 4 分屏后，4 个格子各自可独立切换标签，输入互不干扰
- [ ] AC-2 拖拽分隔条后比例保持，重启应用后恢复
- [ ] AC-3 关闭一个格子，其 3 个标签全部转移到相邻格子且连接未断

### TER-003 · 标签分离为独立窗口

| 字段 | 值 |
|---|---|
| 优先级 | P2 · 兼容性 **C2**（`ALT`） |

**不做的事**：不做「把一个 WebView 里的标签移到另一个 OS 窗口」的跨进程窗口迁移（在 Tauri/WebView2 下不可靠，且会丢失终端状态）。

**做的事**：同一进程内创建**新窗口**（新的 WebView），把会话的渲染目标切到新窗口。会话本身（SSH 连接）仍在 Rust 核心，不重建连接。

**行为**：右键标签 → 「在新窗口中打开」→ 原标签关闭，新窗口出现且内容连续（滚动缓冲保留）。新窗口可再「移回主窗口」。

**验收标准**

- [ ] AC-1 分离后 `tail -f` 输出不中断、缓冲不丢
- [ ] AC-2 分离窗口关闭时，会话按配置终止或保留在后台（可在主窗口恢复）

### TER-004 · 多执行广播

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `F:multiexec` `D:1.3` |

**模式**

| 模式 | 行为 |
|---|---|
| `broadcast-live` | 每次按键实时广播到所有目标（MobaXterm 行为） |
| `broadcast-on-enter` | 本地编辑一行，按 Enter 才广播（更安全，默认） |
| `broadcast-confirm` | 输入完整命令后弹出确认，显示目标数量与环境标签，确认后发送 |

**目标选择**：多选标签 / 多选会话树节点 / 整个文件夹。

**结果聚合视图**（相对 MobaXterm 的核心增强）

1. 命令执行后，按输出哈希分组：相同输出折叠为一行「18 台一致：`active (running)`」。
2. 不一致的展开显示，并可「只看差异」。
3. 每台显示退出码（能取到时）。
4. 可导出结果为 CSV（主机 / 退出码 / 输出摘要）。

**危险命令拦截**（`SEC-011`）

匹配下列模式时，`broadcast-live` 与 `broadcast-on-enter` 均强制转为 `broadcast-confirm` 并红色提示：

```
rm\s+-[rf]{1,2}\s+/(\s|$)      mkfs\.              dd\s+.*of=/dev/
shutdown|reboot|halt|poweroff   :\(\)\s*\{.*\};\s*:   chmod\s+-R\s+777\s+/
>\s*/dev/sd[a-z]                iptables\s+-F         systemctl\s+(stop|disable)\s+.*(sshd|network)
```

规则集可配置（JSON），支持项目自定义；企业策略可强制启用且不可关闭。

**验收标准**

- [ ] AC-1 选择 20 个会话广播 `hostname`，聚合视图显示 20 行不同主机名，且「只看差异」可用
- [ ] AC-2 广播 `rm -rf /` 时被拦截，必须二次确认且确认框显示目标主机数与生产环境数量
- [ ] AC-3 20 个会话中 2 个未就绪，广播时这 2 个被跳过并在结果中标注「未就绪」
- [ ] AC-4 `broadcast-live` 模式下逐字符输入 `ls`，20 台终端逐字符出现

### TER-005 · 配色与字体

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |

**配色**

- 内置 ≥ 20 套：`WindTerm Dark/Light`、`Solarized Dark/Light`、`Dracula`、`Nord`、`Gruvbox Dark/Light`、`One Dark`、`Monokai`、`Tokyo Night`、`Catppuccin Mocha/Macchiato`、`GitHub Dark/Light`、`Windows Terminal Campbell`、`Ubuntu`、`Tango`、`xterm`。
- 每套定义 16 个 ANSI 色 + 前景/背景/光标/选区/加粗/下划线色。
- 导入：iTerm2 `.itermcolors`、Windows Terminal `schemes` JSON、Xresources。
- 导出：JSON。

**字体**

| 项 | 要求 |
|---|---|
| family | 可选系统等宽字体；支持 fallback 链（最多 5 个） |
| size | 8~72 px；`Ctrl+滚轮` 实时缩放；缩放只影响当前会话（可配全局） |
| 行高 | 1.0~2.0 |
| 字距 | -2~+5 px |
| 连字 | 开关（`TER-030`），默认关闭（连字会破坏列对齐判断） |
| 粗体/斜体 | 可映射为「高亮色」而非真粗体（部分字体无粗体字形） |
| 内置字体 | 打包 `JetBrains Mono`（OFL）作为兜底，保证三平台视觉一致 |

**验收标准**

- [ ] AC-1 加载 20 套配色，`printf` 输出 16 色块与真彩色渐变，与参考截图逐色一致（像素比对）
- [ ] AC-2 `Ctrl+滚轮` 缩放后，字符网格与光标位置正确对齐（无半像素错位）
- [ ] AC-3 字体缺失时回退到内置字体并提示一次

### TER-006 · 字符集与编码

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `D:3.2` `H:charset` |

**支持的编码**：UTF-8（默认）、GB18030、GBK、GB2312、Big5、Big5-HKSCS、Shift-JIS、EUC-JP、EUC-KR、ISO-8859-1/2/15、Windows-1252、KOI8-R。

**关键差异（相对 MobaXterm）**：**支持运行时切换编码而不重建会话**。

MobaXterm 的字符集是会话级配置，改了就需重连。实际场景是「连上才发现乱码」——此时用户已经 `cd` 到目标目录、跑了命令，重连成本高。

我们的做法：
1. 保留原始字节流（Rust 侧 ring buffer，最近 1 MB）。
2. 切换编码时，用新编码**重新解码**已有缓冲并重绘。
3. 之后的增量数据用新编码解码。

**自动检测**：连接建立后对首批输出做编码探测（UTF-8 合法性校验 + 常见 CJK 编码启发式），若探测结果与配置不符，显示一条可关闭的提示：「检测到输出可能是 GB18030，是否切换？」——不自动切换（自动切换会造成误判抖动）。

**验收标准**

- [ ] AC-1 远端 `LANG=C` 输出 GBK 中文，切换编码为 GBK 后已显示内容正确重绘，无需重连
- [ ] AC-2 输出 UTF-8 中文与 emoji，列宽计算正确（CJK 占 2 列）
- [ ] AC-3 输出非法 UTF-8 字节，以替换字符显示且不崩溃、不吞掉后续输出

### TER-007 · 背景透明与皮肤

| 字段 | 值 |
|---|---|
| 优先级 | P2 · 兼容性 C2 |

- 背景：纯色 / 图片（拉伸/平铺/居中）/ 透明度 0~100%。
- 平台模糊：Windows 11 Mica/Acrylic、macOS vibrancy、Linux 合成器 blur（尽力而为）。

### TER-008 · 滚动缓冲

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |

| 项 | 默认 | 范围 |
|---|---|---|
| 行数 | 10 000 | 100 ~ 1 000 000 |
| 内存上限 | 256 MB/会话 | 64 ~ 2048 MB |
| 超限策略 | 淘汰最旧行 | 淘汰 / 停止记录并提示 / 自动导出后清空 |

**行为**

1. 滚动条可隐藏（隐藏后仍可 `Shift+PgUp/PgDown`）。
2. 「滚动到上次输出位置」（`TER-033`）：用户上翻后新输出到达不强制跳底，右下角显示「↓ 新输出（N 行）」浮标，点击回到底部。
3. 备用屏切换（vim/less）时缓冲行为遵循 xterm 语义：备用屏不进入滚动缓冲。
4. 提供「清空缓冲」与「导出缓冲后清空」。

**验收标准**

- [ ] AC-1 设置 100 万行缓冲，`seq 1 1000000` 后全部可滚动查看，内存增长符合上限
- [ ] AC-2 上翻 500 行后有新输出，视图不跳动且浮标显示正确行数
- [ ] AC-3 在 `vim` 中滚动不污染主屏缓冲

### TER-009 · 终端内搜索

| 字段 | 值 |
|---|---|
| 优先级 | P1 · 兼容性 C1 |

- `Ctrl+Shift+F` 打开搜索条（顶部或底部，可配）。
- 选项：区分大小写、全词、正则。
- 实时高亮全部命中；显示 `当前/总数`；`Enter` 下一个、`Shift+Enter` 上一个、`Esc` 关闭。

**验收标准**

- [ ] AC-1 在 100 万行缓冲中搜索 `ERROR`，首个结果 ≤ 300 ms 出现，总数准确
- [ ] AC-2 正则 `\d{3,}` 命中数正确，非法正则给出内联错误提示而非崩溃
- [ ] AC-3 命中项在备用屏（vim）中不参与搜索

### TER-010 · 语法高亮

| 字段 | 值 |
|---|---|
| 优先级 | P2 · 兼容性 C1 |
| 来源 | `F:syntax-highlighting` `D:3.2` |

**机制**：行级装饰器。对每条渲染行取纯文本，按规则集匹配，给匹配区间加样式（前景色/背景色/加粗）。不修改字符内容，不影响选择与复制。

**内置规则集**（JSON，可扩展）

| 规则集 | 触发条件 | 示例规则 |
|---|---|---|
| `log-level` | 通用 | `\b(ERROR|FATAL)\b` → 红底；`\bWARN(ING)?\b` → 黄；`\bINFO\b` → 蓝 |
| `log4j` | 匹配 `^\d{4}-\d{2}-\d{2}` | 时间戳灰、级别着色、异常栈红 |
| `nginx-access` | 匹配 `^\d+\.\d+\.\d+\.\d+ .* "(GET|POST)` | 5xx 红、4xx 黄、耗时 > 1s 橙 |
| `java-stack` | 匹配 `^\s+at [\w.$]+\(` | 类名蓝、行号灰 |
| `ip-port` | 通用 | IPv4/IPv6、`host:port`、URL 着色 |
| `git-diff` | 匹配 `^(diff --git|\+\+\+|---)` | `+` 绿、`-` 红、`@@` 青 |
| `python-traceback` | 匹配 `^Traceback` | 异常类型与文件路径着色 |
| `dmesg` | 匹配 `^\[\s*\d+\.\d+\]` | 时间戳灰、`error/fail` 红 |
| `json` | 整行是合法 JSON | key 蓝、字符串绿、数字橙 |

**规则格式**

```json
{
  "name": "log-level",
  "match": { "all": ["\\b(ERROR|FATAL|WARN|INFO|DEBUG)\\b"] },
  "rules": [
    { "pattern": "\\b(ERROR|FATAL)\\b", "style": { "fg": "#ff5555", "bg": "#3a1010", "bold": true } },
    { "pattern": "\\bWARN(ING)?\\b",   "style": { "fg": "#f1fa8c" } }
  ],
  "priority": 100
}
```

**约束**

1. 只对可见区 + 上下各 200 行做匹配（避免长缓冲全量扫描）。
2. 单行规则数上限 64；单条正则编译超时 10 ms 则禁用该规则并警告（防 ReDoS）。
3. `tail -f` 场景下增量行即时应用。
4. 高亮规则可按会话/按标签绑定（例如「这个标签专门看 nginx 日志」）。

**验收标准**

- [ ] AC-1 内置 `log-level` 规则下，`ERROR` 行呈红底，`WARN` 行呈黄色
- [ ] AC-2 自定义规则文件加载后立即生效，无需重启
- [ ] AC-3 故意放入灾难性回溯正则 `(a+)+b`，规则被禁用并提示，UI 不卡死
- [ ] AC-4 `tail -f` 持续输出时高亮即时生效且 CPU 占用 < 5%

### TER-011 · 选择 / 复制 / 粘贴

| 字段 | 值 |
|---|---|
| 优先级 | P0 · 兼容性 C1 |
| 来源 | `D:3.2` `H:rightclick-paste` |

**选择**

| 操作 | 行为 |
|---|---|
| 拖拽 | 字符级选择 |
| 双击 | 选词；分隔符可配（`LeftDelimChars`/`RightDelimChars` 等价物，默认 `/~+-.&?$%`） |
| 三击 | 选整行（不含换行） |
| `Ctrl+Alt+拖拽` | 列（块）选择（`TER-012`） |
| 选择时自动复制 | 默认开启（类 Unix 终端习惯）；可关闭 |
| `Shift+拖拽` | 强制本地选择（即使应用开启了鼠标上报） |

**复制粘贴**

| 快捷键 | 行为 |
|---|---|
| `Ctrl+Shift+C` / `Ctrl+Insert` | 复制 |
| `Ctrl+Shift+V` / `Shift+Insert` | 粘贴 |
| `Ctrl+C` | **发送 SIGINT**（不复制），除非有选区且未运行前台进程——此行为可配为「总是复制」 |
| 右键 | 默认弹菜单；可配为「粘贴」，此时菜单用 `Ctrl+右键`/`Shift+右键` 唤出 |
| 中键 | 粘贴主选区（Linux 桌面习惯） |

**粘贴处理**

1. 内容规范化：`\r\n` → `\r`（终端语义），去除尾部空白（可配）。
2. 含 ≥ 2 个换行时确认（`TER-013`）。
3. 超过 1 MB 时提示并分块发送（`TER-014` 的节流）。
4. 终端处于 bracketed paste 模式时用 `\e[200~...\e[201~` 包裹。

**验收标准**

- [ ] AC-1 双击选中 `user@host:/var/log` 全串（默认分隔符下不切断）
- [ ] AC-2 开启「右键粘贴」后，右键直接粘贴，`Ctrl+右键` 弹出菜单
- [ ] AC-3 粘贴 100 行文本时弹出确认，取消后终端未收到任何字节
- [ ] AC-4 在 vim 中粘贴多行不触发自动缩进（bracketed paste 生效）

### TER-012 · 列（块）选择

`Ctrl+Alt+拖拽` 选中矩形区域；复制时按行拼接（每行取该列区间的字符），保留换行。用于选中 `ps`/`netstat` 的某一列。

### TER-013 · 多行粘贴告警

- 触发条件：粘贴内容含 ≥ 2 个 `\n`（可配为 ≥ 1）。
- 对话框显示：行数、字符数、前 3 行预览、目标会话名与环境标签。
- 提供「本次不再提示」与「对该会话永久不再提示」。
- 白名单：检测到当前前台进程为 `vim`/`nano`/`less`/`man` 时不告警（这些程序期望多行输入）。

### TER-014 · 粘贴延迟

按行或按字节节流，用于慢速链路或对输入速率敏感的设备（如串口）。默认关闭。提供 10/25/50/100 ms 预设与自定义。

### TER-015 · 终端日志记录

| 字段 | 值 |
|---|---|
| 优先级 | P1 · 兼容性 C1 |
| 来源 | `D:3.2` `H:log-encoding` |

**MobaXterm 的问题**：只提供「记录原始流」，用户拿到的是带 ANSI 转义序列的二进制文件，用文本编辑器打开是乱码（其帮助文档 §6.7.13 明确承认这一点，并把解决方案推给用户手动清理）。

**我们的规格**

| 模式 | 输出 | 用途 |
|---|---|---|
| `plain`（默认） | 剥离 ANSI 转义后的纯文本，UTF-8 | 直接 `grep`、发给同事、存档 |
| `ansi` | 保留 SGR 颜色，剥离其他控制序列 | 需要保留颜色的报告 |
| `raw` | 原始字节流（含全部控制序列） | 精确回放、问题复现 |

**文件命名**：`<会话名>_<YYYYMMDD-HHMMSS>.log`，可配模板（支持 `{session}`、`{host}`、`{user}`、`{date}`、`{time}`、`{pid}`）。

**行为**

1. 按会话开关；也可全局「所有会话自动记录」。
2. 按大小滚动（默认 10 MB × 5 份）或按时间（每日）。
3. 记录内容可选：仅输出 / 仅输入 / 双向（默认仅输出，避免记录密码）。
4. **输入记录默认关闭**，开启时警告「会记录你输入的所有内容，包括可能的密码」。
5. 停止记录时写入文件尾标记（含会话名、时长、行数）。

**验收标准**

- [ ] AC-1 `plain` 模式下 `ls --color=always` 的输出写入文件后无转义字符，`grep` 可用
- [ ] AC-2 `raw` 模式下文件可被我们的回放器还原为相同画面
- [ ] AC-3 开启输入记录时弹出警告，且密码输入（`echo off` 期间）被自动屏蔽

### TER-016 · 保存终端文本

- 范围：可见区 / 全部缓冲 / 选中内容。
- 格式：纯文本 / 带 ANSI / HTML（保留颜色与字体，可直接贴邮件）。
- 默认文件名含会话名与时间。

### TER-017 · 标签活动指示

- 非活动标签有新输出 → 显示圆点。
- 可选「仅当输出匹配关键词时提醒」（关键词可按会话配置），此时圆点变为彩色并触发系统通知（`SYS-012`）。
- 活动状态在标签被激活时清除。

### TER-018 · 关闭确认

- 触发：会话有前台进程（非 shell 本身）或处于 `broadcast` 目标中。
- 对话框：会话名、前台进程名（能取到时）、「关闭 / 取消 / 后台保留」。
- 全局可配「永不确认」（不推荐，设置页标注风险）。

### TER-019 · 标题锁定

锁定后忽略远端 `OSC 0/1/2`。用于防止远端程序（如 `screen`、某些 shell 主题）把标签名改乱。

### TER-020 · 快捷键体系

见 §5 完整键位表。要求：全部可重绑、冲突检测、按作用域分组、可导出/导入、可恢复默认。

### TER-021 · URL / 路径识别

| 类型 | 正则示例 | `Ctrl+Click` 行为 |

### TER-024 · Truecolor

### TER-025 · Unicode 宽字符

### TER-034 · 大量输出流控

| 字段 | 值 |
|---|---|
| 优先级 | **P0**（`NFR-003` 的实现手段） |

**问题**：`cat` 一个 500 MB 文件或 `yes` 时，如果无节制地把数据推给 WebView，会造成：内存暴涨 → GC 卡顿 → 渲染阻塞 → 用户以为「卡死」→ 强制关闭丢会话。

**方案：信用制背压**

```
Rust 侧                     前端
  │                          │
  ├─ 读取 PTY/SSH 数据        │
  ├─ 放入 ring buffer        │
  ├─ 若未确认字节 > 高水位 ──┤ 停止读取（对 SSH 通道窗口不 ACK）
  │                          │
  │  ←── term_ack(n) ────────┤ 渲染完成 n 字节后回报
  │                          │
  └─ 若未确认字节 < 低水位 ──→ 恢复读取
```

| 参数 | 默认 |
|---|---|
| 高水位 | 2 MB 未确认 |
| 低水位 | 512 KB |
| 单次投递上限 | 64 KB |
| 渲染节流 | 每帧最多处理 8 ms 的数据，剩余留到下一帧 |

**可观察行为**：`yes` 持续输出时，UI 保持可交互（可滚动、可 `Ctrl+C`），终端显示追赶状态；数据不丢（ring buffer 溢出时才丢弃并明确提示「输出过快，已丢弃 N 行」）。

**验收标准**

- [ ] AC-1 `cat /dev/urandom | base64` 持续 60 s，UI 保持可交互，`Ctrl+C` 能立即中断
- [ ] AC-2 `seq 1 5000000` 后行数与预期一致（无丢行）
- [ ] AC-3 人为把前端渲染降速到 10 fps，数据仍不丢，只是显示滞后
- [ ] AC-4 内存峰值不超过 `NFR-002` 的 2 倍

### TER-035 · 宏录制与回放

| 字段 | 值 |
|---|---|
| 优先级 | P1 · 兼容性 C1 |
| 来源 | `F:macros` |

**录制内容**：键入序列 + 时间戳 + 窗口大小变化 + 可选的特殊动作（发送 Ctrl 组合、粘贴、等待输出匹配）。

**数据格式（JSON，可读可编辑）**

```json
{
  "name": "restart-nginx",
  "version": 1,
  "createdAt": "2026-11-02T10:00:00Z",
  "steps": [
    { "t": 0,    "type": "text",  "value": "sudo systemctl restart nginx" },
    { "t": 320,  "type": "key",   "value": "Enter" },
    { "t": 900,  "type": "wait",  "expect": "active \\(running\\)", "timeoutMs": 10000 },
    { "t": 0,    "type": "text",  "value": "systemctl status nginx" },
    { "t": 150,  "type": "key",   "value": "Enter" }
  ]
}
```

**回放模式**

| 模式 | 行为 |
|---|---|
| 原速 | 按录制时间戳回放（默认） |
| 加速 | 时间压缩为 1/N（N 可配 1~10） |
| 逐字 | 每个字符间隔固定 20 ms（适配慢速设备/串口） |
| 单步 | 手动逐步执行，适合教学与排错 |

**约束**

1. 录制期间**不记录**终端处于 `echo off` 时输入的字符（避免记录密码）。
2. 回放前显示将执行的步骤摘要，并要求确认。
3. 可绑定到快捷键、会话启动、文件夹批量操作。
4. 宏可导出/导入，供团队共享。

**验收标准**

- [ ] AC-1 录制 10 步操作后回放，远端状态变化与手工执行一致
- [ ] AC-2 录制过程中输入 `sudo` 密码，宏文件中不含该密码
- [ ] AC-3 `wait` 步骤在超时后中止宏并报错，不继续执行后续步骤
- [ ] AC-4 宏可绑定到文件夹，批量对 5 台机器执行

### 6.2 键盘编码表

需要正确编码的键：26 个字母、10 个数字、标点、`Enter`、`Tab`、`Backspace`（`^H`/`^?` 可配）、`Esc`、`Delete`、`Insert`、`Home`/`End`、`PgUp`/`PgDn`、4 个方向键、`F1`~`F12`（含 `Shift`/`Ctrl`/`Alt` 组合）、小键盘。

**修饰键组合规则**（xterm 标准）：`Ctrl+字母` → `0x01~0x1A`；`Alt+键` → `ESC` 前缀；`Ctrl+方向键` → `\e[1;5A` 等。

**中文输入法**：终端内的 IME 组合过程必须由前端处理（显示候选窗），提交时才把字符编码发给远端。**不允许**把组合过程中的按键直接发送（会导致远端收到拼音字母）。

### 6.3 尺寸协商

- 窗口变化 → 去抖 50 ms → 计算新 `cols×rows` → 发送 `SSH window-change` / `TIOCSWINSZ`。
- 分屏时每格独立计算。
- 缩放字号后重新计算并发送。
- 最小尺寸 20×4，低于此值不发送。

### 6.4 流控（`TER-034`）

见 `TER-034` 规格。设计细节见 `design/02` §5 与 `design/03` §6。

## 7. 宏（补充说明）

`TER-035` 已给出规格。补充：

- 宏可绑定到：快捷键、会话启动（连接后自动执行）、文件夹右键菜单。
- 宏库为全局共享，可在会话间复用。
- 宏执行时终端显示「宏执行中：restart-nginx（步骤 2/5）」，可中止。
- 支持「参数化宏」：录制时把某些输入标记为变量（`{{host}}`），回放时提示填入。这是 MobaXterm 没有的能力。
