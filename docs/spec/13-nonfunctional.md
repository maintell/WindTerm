# 13 · 非功能需求

承接需求：`NFR-001`~`NFR-016`

## 1. 度量原则

非功能需求与功能需求的根本区别：**它们没有「做完了」，只有「达标 / 不达标」，而且是持续回归的。**

因此本文件的每条需求必须包含四个要素，缺一不可：

1. **阈值**（可测量）
2. **测量点**（从哪个时刻到哪个时刻）
3. **测量环境**（硬件、数据规模、OS）
4. **门禁规则**（超标时 CI 怎么处理）

并且全部通过 `wt bench` 子命令可复现——不允许「只在开发者机器上跑过一次」的指标。

## 2. 性能

### NFR-001 · 冷启动时间

| 字段 | 值 |
|---|---|
| 阈值 | **P95 ≤ 1200 ms**；P50 ≤ 900 ms |
| 测量点 | 进程创建 → 主窗口可接受键盘输入（首个终端渲染完成且输入已绑定） |
| 环境 | Windows 11 / 4 核 / 16 GB / NVMe SSD / 预置 8 个会话 / 冷缓存（首次启动） |
| 方法 | `wt bench startup --runs 30 --json`，取 P50/P95 |
| 门禁 | P95 超过阈值 15% 连续 2 次构建 → CI 失败 |

**分解预算**（用于定位回归）

| 阶段 | 预算 |
|---|---|
| 进程启动 + 动态库加载 | 200 ms |
| WebView 初始化 | 350 ms |
| 配置与会话加载（8 个） | 100 ms |
| 前端框架挂载 | 250 ms |
| 首个终端创建与渲染 | 200 ms |
| 余量 | 100 ms |

### NFR-002 · 内存占用

| 场景 | 阈值 |
|---|---|
| 空闲（无会话） | ≤ 90 MB |
| 3 个 SSH 会话（各 10 000 行缓冲） | ≤ 150 MB |
| 20 个 SSH 会话 | ≤ 450 MB |
| 1 个 RDP 会话（1080p） | +80 MB |
| 1 个 VNC 会话（1080p） | +60 MB |

| 字段 | 值 |
|---|---|
| 测量点 | 进程 RSS 总和（含 WebView 子进程） |
| 环境 | 同上；会话均为空闲（无输出） |
| 方法 | `wt bench mem --sessions 3 --json` |
| 门禁 | 超出 20% → CI 失败 |

**内存增长约束**：连续运行 24 h、每 10 s 产生 100 行输出，RSS 增长 ≤ 15%（无泄漏）。

### NFR-003 · 终端吞吐与流控

| 字段 | 值 |
|---|---|
| 阈值 | 持续 **≥ 20 MB/s** 且**零丢字节**；UI 帧率 ≥ 30 fps；输入延迟 ≤ 50 ms |
| 测量点 | 远端 `dd if=/dev/zero bs=1M count=200 \| base64` 的端到端处理 |
| 环境 | 千兆局域网，RTT 1 ms；终端 120×40 |
| 方法 | `wt bench throughput --mb 200 --json`，校验接收字节数与源一致 |
| 门禁 | 低于 20 MB/s 或出现丢字节 → CI 失败 |

**辅助指标**：`yes` 持续输出 60 s，期间 `Ctrl+C` 响应时间 ≤ 200 ms。

### NFR-004 · SFTP 传输性能

| 场景 | 阈值 |
|---|---|
| 单文件 1 GB 上传 | ≥ 60 MB/s |
| 单文件 1 GB 下载 | ≥ 80 MB/s |
| 1000 个 10 KB 小文件上传 | ≥ 300 文件/s |
| 目录列表（5000 项） | ≤ 2 s |

| 字段 | 值 |
|---|---|
| 环境 | 千兆局域网，服务端 OpenSSH 8.0，`aes128-gcm` |
| 方法 | `wt bench sftp --json` |
| 门禁 | 低于阈值 25% → CI 失败 |

### NFR-005 · 图形会话延迟

| 场景 | 阈值 |
|---|---|
| RDP 局域网输入到显示 | ≤ 60 ms（P95） |
| RDP 视频播放 | ≥ 25 fps（1080p，EGFX） |
| VNC ZRLE 静态画面带宽 | ≤ 1 Mbps（1080p） |
| VNC 帧解码与绘制 | ≤ 33 ms |

| 字段 | 值 |
|---|---|
| 环境 | 千兆局域网；Windows Server 2019；1080p |
| 方法 | `wt bench rdp --json`（发送合成输入并测量画面变化时间） |
| 门禁 | 超阈值 30% → 告警（不阻塞，因受环境影响大） |

### NFR-006 · 并发会话

| 场景 | 阈值 |
|---|---|
| 50 个 SSH 会话 | 稳定运行 1 h，内存 ≤ 900 MB，UI 可交互 |
| 200 个 SSH 会话 | 不崩溃；UI 允许卡顿但操作最终生效 |
| 20 个并发传输 | 全部完成，无死锁 |

**方法**：压测脚本对本地 `sshd` 建立 N 个会话并周期性执行命令。

## 3. 可靠性

### NFR-007 · 稳定性

| 指标 | 阈值 |
|---|---|
| 崩溃率 | < 0.1 次 / 千会话小时 |
| 连接建立成功率 | ≥ 99.5%（排除凭据错误） |
| 传输成功率 | ≥ 99.9%（排除权限/空间错误） |
| 隧道重连成功率 | ≥ 99%（网络恢复后 30 s 内） |

**统计来源**：本地诊断日志（不上报）。用户可在「关于 → 运行统计」查看自己的数据。

### NFR-008 · 故障恢复

| 场景 | 要求 |
|---|---|
| 应用崩溃 | 重启后 10 s 内提供会话恢复；不丢失会话/隧道/设置数据 |
| 数据库损坏 | 启动时检测（`PRAGMA integrity_check`）；损坏则从 `.bak` 恢复，并向用户报告丢失范围 |
| 保险库损坏 | 不自动删除；提示「保险库损坏，可从备份恢复」，提供 `vault.bin.bak` |
| 磁盘满 | 写操作失败时给出明确错误，不进入不一致状态（所有写入都是「临时文件 + rename」） |
| 网络闪断 | 按 `SES-027` 重连；不丢失滚动缓冲 |

### NFR-009 · 长时间运行

- 连续运行 7 天（每 10 s 一次输出）：
  - RSS 增长 ≤ 20%
  - 无文件句柄泄漏（句柄数增长 ≤ 50）
  - 无 UI 卡顿累积（第 7 天输入延迟与第 1 天差异 ≤ 20%）

## 4. 安全基线

### NFR-010 · 数据安全

| 要求 | 验证 |
|---|---|
| 无明文凭据落盘 | 全盘 `grep` 已知密码字符串，零命中 |
| 无明文凭据进日志 | 同上，对日志目录 |
| 保险库格式符合 `spec/11` §4.2 规范 | 用独立实现（Python）解密成功 |
| 内存中的密钥被 `zeroize` | 代码审计 + 单元测试（`Drop` 后内存清零） |
| 传输默认使用现代算法 | 算法列表审计；禁用项有测试 |
| 主机密钥默认强制校验 | 无全局关闭开关（代码审计） |

### NFR-011 · 依赖安全

- CI 每次构建跑 `cargo-audit` 与 `cargo-deny`。
- 存在 `RUSTSEC` 高危漏洞 → 构建失败。
- 许可证白名单：`MIT`、`Apache-2.0`、`BSD-2/3`、`ISC`、`Unicode-3.0`、`Zlib`、`MPL-2.0`（弱传染，允许动态链接）。GPL 类必须显式登记（`spec/01` §5.2）。

## 8. 可维护性

### NFR-017 · 架构约束

| 约束 | 验证 |
|---|---|
| crate 依赖无环 | `cargo-deny` + 自定义脚本（拓扑排序检查） |
| 核心 crate 不依赖 UI 层 | 依赖图检查（`wt-core` 不得依赖 `wt-ui`） |
| 单文件 ≤ 800 行 | CI 检查（超限需注释说明） |
| 单函数圈复杂度 ≤ 15 | `clippy::cognitive_complexity` |
| 公共 API 有文档注释 | `#![warn(missing_docs)]` |

### NFR-018 · 测试覆盖

| 层 | 目标 |
|---|---|
| 核心 crate（协议、加密、数据模型） | 行覆盖 ≥ 70%，分支覆盖 ≥ 60% |
| 前端组件 | 行覆盖 ≥ 50% |
| E2E（7 条 FLOW） | 100% 覆盖 |
| 协议互通 | 每个支持的服务端版本至少 1 条用例 |

**注意**：覆盖率是**下限**而非目标。协议解析类代码必须有针对边界条件的用例（畸形输入、超长字段、非法状态机转换），而不是靠覆盖率数字。

### NFR-019 · 结构测试

以下检查在 CI 中作为测试执行（不是脚本）：

1. 需求 ID 闭合性（`spec/03` §6 的五条规则）。
2. 每个 `P0` 需求有对应 E2E 或集成测试。
3. 语言文件键对齐。
4. 无硬编码用户字符串。
5. ADR 索引与正文一致。
6. 文档内部链接无死链。

## 9. 可观测性

### NFR-020 · 日志与诊断

| 要求 | 说明 |
|---|---|
| 结构化日志 | JSON 行，字段：`ts`、`level`、`target`、`msg`、`sessionId`、`span` |
| 分级 | `error`/`warn`/`info`/`debug`/`trace`；默认 `info` |
| 脱敏 | 密码、私钥、token 自动替换为 `***`；有单元测试 |
| 轮转 | 单文件 ≤ 10 MB，保留 5 份 |
| 诊断包 | `wt diag bundle` 生成 zip：日志、配置（脱敏）、系统信息、连接诊断结果；**不含**会话内容与凭据 |
| 崩溃转储 | 默认关闭；开启时生成最小 minidump，本地保存，不自动上传 |

### NFR-021 · 性能可观测

- 内置性能面板（`Ctrl+Shift+Alt+P`）：FPS、IPC 往返延迟、内存、各会话吞吐。
- 用于用户自查与问题报告。

## 11. 升级兼容

### NFR-024 · 数据格式版本

| 要求 | 说明 |
|---|---|
| 配置/数据库/保险库都有版本号 | 文件头或表结构版本 |
| 升级只向前 | 新版本能读旧数据；旧版本读新数据时明确报错而非静默损坏 |
| 跨 1 个 minor 版本平滑 | 从 1.0 升 1.1、1.1 升 1.2 均可 |
| 跨 major 需迁移向导 | 2.0 时提供显式迁移步骤 |
| 降级保护 | 检测到数据版本高于程序版本 → 拒绝启动并提示（避免损坏） |
| 升级前自动备份 | 复制 `data.db` 与 `vault.bin` 到 `backup/<version>/` |

### NFR-025 · 升级测试

CI 中执行：安装 N-1 版本 → 造数据（20 会话 + 5 隧道 + 保险库）→ 升级到 N → 校验数据完整 → 执行 7 条 FLOW 的冒烟子集。
