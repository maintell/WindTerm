# 04 端口转发与代理

三种隧道解决三类问题，都在左侧「隧道」面板里建。

## `-L` 本地转发：把远端端口搬到本地

典型场景：数据库只允许服务器访问，你想用本机客户端连它。

填「本地端口」（`0` 表示随机分配，建好后会回填真实端口）和「目标主机:端口」（**从服务器视角**看的目标），启动后连 `127.0.0.1:本地端口` 就行。

## `-R` 远程转发：把本机端口搬到服务器

反向的场景：同事要从服务器访问你本机跑的服务。

端口填的是**服务器上**的端口（占位提示会变），目标是本机的地址。需要服务器允许 `AllowTcpForwarding`；监听非回环地址还要 `GatewayPorts`，否则会被拒绝——错误信息会点名这两个开关。

## `-D` 动态代理：本地 SOCKS5

切到「动态代理」后不需要目标地址：它在本机开一个 SOCKS5 代理，每个连接自己带目标（域名交给服务器解析）。

可选的**用户名密码认证**（RFC 1929）：填了用户名就必须填密码，只填一半会直接报错。

> 带认证的隧道**不会保存配置**（口令不写进配置文件）。重启后要重填，界面会提示「配置未保存」。这是有意的取舍。

## 几个共通的点

| 现象/设置 | 说明 |
|---|---|
| 灰灯 | 隧道停了但配置还在库里，可以「启动」或「删除」 |
| 红点 + 上次错误 | 承载连接断了但监听还在，继续显示绿灯就是骗人 |
| 「拒绝 N」 | 超过每隧道并发上限（64）被立刻关闭的连接数，与累计连接数分开计 |
| 允许局域网访问 | 监听 `0.0.0.0` 会让同网段的人也能用，必须显式勾选 |
| 解锁保险库后自动拉起 | 勾了以后，保险库解锁/打开面板时自动启动；带代理认证的隧道这个勾选框会被禁用 |

## 连不上怎么排查

1. 看隧道列表里的「上次错误」——它比日志直接；
2. `-L`/`-D` 失败多半是本地端口被占；
3. `-R` 失败看服务端 `AllowTcpForwarding` / `GatewayPorts`；
4. 隧道通了但业务不通，用 `telnet 127.0.0.1 端口` 先确认监听存在。
